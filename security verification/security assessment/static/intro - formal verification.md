### **Formal Verification**

**Formal verification** is a **static analysis** method applied to a **formal model** of a system, rather than to the system itself. A **formal model** is a mathematically rigorous and unambiguous representation, such as a **state machine** or **graph**, typically created during the **design** or **requirements analysis** phases. The purpose of formal verification is to provide **high security assurance**, including **correctness proofs** regarding the model. However, this approach has a notable weakness: it cannot guarantee that the actual system behaves correctly, as it assesses the model, not the implementation.

In the development process, formal verification can involve **formal specifications** for requirements and design. Larger systems may have multiple versions of design specifications, including **high-level** and **low-level** models. The implementation usually represents the **real system** and lacks the formal properties of a model, making formal analysis challenging. However, informal verification methods, such as **testing**, can be performed on the implementation. Interestingly, compiling code can serve as a form of formal verification because it checks the **syntax** of the code.

**Model extraction** plays a crucial role in **a-posteriori formal verification**. It involves deriving a formal model from the code, which can then be analyzed for compliance with the requirements without executing the code. Although certain parts of the code (like syntax) are formally analyzable, others (such as semantics) are not as straightforward. For instance, different compilers may interpret unspecified aspects of programming languages differently, leading to variations in behavior.

**Functional programming languages**, like **ML**, often employ formal semantics, allowing the code itself to function as a formal model. In contrast, languages such as **C**, **Java**, and **Python** lack formal semantics, leading to multiple possible interpretations by various compilers. This distinction highlights the differences in the ability to perform formal verification based on the programming language used.
