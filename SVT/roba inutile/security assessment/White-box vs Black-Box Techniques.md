

### White-Box Techniques
- **Overview**: All information about the target system is available, including:
  - Specifications
  - Design documentation
  - Source code
- **Benefits**: Allows for in-depth analysis and understanding of the system, facilitating more thorough testing and identification of vulnerabilities.

### Black-Box Techniques
- **Overview**: No information about the target system is available to the assessor.
- **Methodology**:
  - Information must be extracted from the system itself.
  - The assessor behaves like a real attacker, simulating the same conditions that an external threat would encounter.
- **Benefits**: Helps to identify vulnerabilities from an attacker’s perspective, ensuring that security measures are effective against real-world threats.

### Grey-Box Techniques
- **Overview**: An intermediate situation between white-box and black-box.
- **Methodology**:
  - Some information is provided, but not the complete set of details.
- **Benefits**: Balances between the thoroughness of white-box testing and the realistic attack scenarios of black-box testing.
